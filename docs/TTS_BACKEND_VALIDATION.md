# モデル交換設計・Irodori廃止の実装と検証

2026-10-22。Windows、RTX 5080、CUDA、OmniVoiceのローカル検証。

## 実装結果

- Backend契約と登録一覧を導入。実装IDとモデル構成IDを分離し、OmniVoiceを最初のアダプターとした。
- 能力情報に基づいて言語・参照時間・文字起こし・話速・生成設定を検証し、画面の項目を生成する。モデル選択は設定画面に移動。
- 翻訳・ASRはTTSと独立した所有ワーカーへ分離。現在の補助依存環境はOmniVoice用Pythonを再利用するが、TTSモデルをロードせず動作し、TTSの切替でも停止しない。
- アプリ用Pythonをruntime/app/.venvへ独立。torchとirodori_ttsが存在しない環境でテストを実行した。
- モデルと設定・声素材の版をジョブ受付時に固定。モデル別に準備特徴と定型句キャッシュを識別する。
- 旧APIは410、旧Irodoriの明示要求は422。参照不足は503で、別の声やモデルへフォールバックしない。
- 旧設定はschema v3へ移行。元WAV・手動参照・履歴は保持。新規標準4声はOmniVoiceで生成できる。

追加の[発話待ち時間の改善](LATENCY_IMPROVEMENTS_2026-10-22.md)を含む現在の検証結果を記載する。

## 実生成と実API

`scripts/verify_omnivoice.py`でIrodoriを使わず6.2秒の参照音声を新規生成。準備後の日本語合成は962.5ms、英語は973.7ms。有音の24,000HzモノラルWAVを確認。独立したASRで生成参照の文章を認識し、CPU翻訳「駅で待っています。」→「I'll be waiting at the station.」を確認した。

`scripts/start_backend_validation.py`で専用ポート8111・専用データを起動し、`scripts/verify_backend_api.py`で次を確認した。

- モデル一覧、標準4声すべての作成と参照条件。
- 日本語WAV、定型句キャッシュ再利用、日英翻訳後の英語WAV。
- ジョブ応答に参照パス・モデルパスが出ないこと。
- 履歴保存・同じWAVの取得、生成した試験用音声の登録と削除。
- 旧APIの410、Irodori明示指定の422、外部Origin/Hostの403。
- 取消後の音声取得が410となること。

各1回のAPI経由の測定は検証用JSONに記録した。初回の翻訳は補助ワーカー・モデル読み込みを含むため、準備後の合成時間と混同しない。統計的なp50/p95・物理スピーカー遅延・性能保証ではない。

検証用WAV・計測JSONは.runtime/omnivoice-smoke.json、.runtime/backend-validation/api-evidence.json等へ保存し、配布物には含めない。

## 既存データとIrodori専用物の退避

ローカルconfig.local.jsonをバックアップ付きでschema v3へ移行し、保存設定をOmniVoiceへ移行した。移行前DBバックアップと現在DBのvoices、history、voice_profilesが一致することを確認。元WAV6件のハッシュも退避前後で一致した。辞書・定型句は移行処理で削除しない。

Echo Ego内のruntime/Irodori-TTS、runtime/models/MF、旧hf-cache・download-cache、旧.venv、data/latentsは、.runtime/retired-irodori-20261022へ相対構造を保って退避した。manifest.jsonに元の場所と退避先を記録した。永久削除はしていないため、ディスク空き容量は増えない。

外部システムの環境は変更していない。既存の追加プリセットフォルダー設定も保持しており、そのWAVは引き続き参照素材として利用できる。旧Irodori環境を起動する依存ではない。

退避後、通常のscripts/start.ps1 -NoBrowserでポート8100を起動。既存標準WAVを使う試聴モードのジョブで、有音の24,000Hz WAVを確認した（初回2.67秒、再起動後3.03秒）。通常環境で日英翻訳後の英語合成と、独立ASRの下書き生成も確認した。試聴を履歴へ保存せず、ASR下書きも参照設定へ保存していない。最終確認後も元WAV6件・声・履歴・手動参照テーブルは移行前と一致した。アプリは通常ポートで起動した状態にする。

復元時はアプリを停止し、現在のデータも保存してから、退避manifestに従って旧環境を元の位置に戻す。旧ソースとconfig.local.v1-backup.json、必要ならdata/echo-ego.before-backends.sqlite3を組み合わせる。移行後の新しいデータを旧バックアップで上書きしないこと。
