# Echo Ego リリースに向けた改善案

初回UI変更時の提案記録です。2026-10-04の追加実装で声管理・設定/履歴保存・定型句・キュー・導入設定を反映しました。現状と検証範囲は[実装・検証記録](IMPLEMENTATION.md)、操作は[マニュアル](USER_GUIDE.md)を参照してください。以下の「現在」は初回UI変更時点の記述です。

## 今回反映した内容

- 小さなソフト名と「発話」「履歴」のナビゲーション。
- 発話と履歴を別画面へ分離。入力文・声・速さ・生成設定は画面切り替えで保持。
- 履歴に音声生成完了時刻を表示。サーバーでUTC記録、画面は日本時間・秒単位。
- 個別削除・全件削除・直前の削除を取り消す操作。
- 履歴から再生、日時を含む名前でWAV保存。
- 技術的な設定と詳細計測は折りたたみへ移動。
- 音声の再生中にステータスが「準備完了」へ戻っていた問題を修正。
- 自分の声の登録を、キーボードでも操作できるボタンへ変更。

履歴は現在もタブ内の最大10件。再読み込み・タブを閉じると消える。直前の削除分は「元に戻す」のため、次の削除またはタブ終了までメモリーに保持する。

ブラウザーでEnter発話、生成日時の表示、個別削除・全件削除と各取り消し、復元後の音声再生を確認。入力途中の文と話す速さが画面の往復後も残ることを確認した。JavaScript構文チェックも通過。本人の声の音質評価や別PCの配布検証は今回実施していない。

## 優先度：リリース前に整える

### 1. 履歴と設定の保存方針

履歴のローカル保存をユーザーが選べるようにする。保存しないモード、保存件数・容量・期間の上限、音声込みの削除を用意する。保存日時は現在の生成完了時刻を引き継ぐ。

声・話す速さ・ウィンドウ位置等の設定は、発話内容とは分けて保存する。保存失敗時は画面に知らせ、入力中の文を失わない。大量の音声を保存しても送信から発話までの経路を待たせない。

### 2. 自分の声を扱いやすくする

録音、試聴、名前変更、削除、お気に入りを追加する。ランダムなファイル名をそのまま表示する現在の登録画面を改める。録音時はマイク入力と録音時間・音量を確認できるようにする。

名前変更で参照音声のキャッシュが壊れないよう、内部IDと表示名を分離する。声の削除では録音と前処理キャッシュを一緒に整理する。プリセットは音声ごとの利用・配布条件を整理し、配布に含められるものを決める。

### 3. 会話での待ち時間を減らす

定型句は編集・並び替え・ショートカット設定を可能にし、事前生成しておく。声や速さ、読み設定が変わったら対応する音声を更新する。

会話の発話キューを追加する。今の試作品は生成中の送信を待つため、「再生中に次の文を準備」「生成待ちの確認」「待ち行列の取り消し」を扱えるようにする。停止時に旧結果が再生されない現在の仕組みを維持する。

### 4. 導入と終了をアプリ内で完結

このPCの既存Irodori環境への依存をなくし、配布用の環境設定・GPU確認・モデル取得・起動エラー案内を用意する。既存のStudioを変更しない。

アプリ終了時のGPU解放、常駐の有無、二重起動を整理する。別PCでのクリーン導入を検証し、起動時間と会話中の遅延を分けて表示する。

## 次の段階で追加したい機能

- 出力スピーカー・ヘッドホンの選択、音量、再生確認。
- 発話・停止のショートカット。常駐利用では他アプリのキー操作との競合を避ける。
- 人名・専門語の読み辞書。表示する文章と発話用の読みを分離する。
- 通話へ音声を送る場合の出力先と導入手順。通常のスピーカー発話とは別に検証する。
- 実会話で読みの正しさ、欠落、余計な発話、本人の声の類似性、長い文での遅延を評価する。

## 次の実装でおすすめする順序

「音声の名前変更・試聴・お気に入り」→「設定保存と履歴保存の選択」→「定型句の事前生成」→「配布環境」。

性能については起動直後・暖機後・声変更・長さの違う文を分けて測定し、再生スケジュール時刻と実際に聞こえる時刻を区別する。
