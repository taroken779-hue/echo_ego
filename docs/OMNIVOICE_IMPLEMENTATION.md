# OmniVoice・読み辞書 実装記録

2026-10-19。ローカルでの実装・検証記録。Irodoriとの実聴による優劣判定は未実施。

## 実装

- Torchを制御APIから分離し、エンジン別の所有ワーカーを起動。Irodoriの既存環境を保持し、OmniVoiceは別環境を構築。
- 日英のモード切替、CPU日英翻訳、原文/訳文/発話文の分離、完成WAV再生。
- 受付時の声・モデル・辞書の固定、FIFO・要求IDによる二重生成防止、取消時の遅い結果の破棄、件数/容量/期限の上限。
- 声の参照区間・文字起こしの登録、参照プロンプト再利用、声準備時のウォームアップ。
- 読み辞書の旧設定移行、最長一致・非再帰・有効切替・文全体一致・プレビュー・未保存ドラフト試聴、revision/ETagによる競合検出。
- 履歴に訳文・発話文・辞書版・声版・エンジン情報を追加。定型句キャッシュを言語/モデル/読み/声で分離。
- セットアップ、固定依存、モデルmanifest、操作ガイド、配布allowlistを更新。

## 確認結果

単体/APIの21件で、保存処理、読みの重なり/非再帰/適用範囲、旧辞書の保持、revision競合、長さと制御記号、取消、要求ID、大量取消後の保持上限と継続実行、クライアント別上限、旧APIのETag、英語への原文受渡し、WAV取得、Origin拒否を確認。

RTX 5080で、本人録音を使わず生成した参照音声からOmniVoiceの日英WAVを作成。先頭有音・長さ・WAVを確認し、CPU翻訳「駅で待っています。」→「I'll be waiting at the station.」を確認した。

初回の日本語生成は約8.8秒、その後の英文生成は約0.97秒だった。声準備時のウォームアップを追加し、稼働アプリのAPI経路で以下を確認した。

| 条件 | 計測結果 |
| --- | --- |
| 日本語、16step、読み辞書ドラフト適用 | 合成約0.97秒、要求〜音声取得約1.02秒 |
| 日英翻訳＋英語発話、16step | 翻訳約1.37秒、合成約0.90秒、要求〜音声取得約2.53秒 |

各1回の短文測定。p50/p95でも実スピーカー遅延でもなく、声準備・モデル切替の時間も含まない。英語モードの仮目標p50 1.5秒を達成したという結果ではない。

画面で日本語の新ジョブ経路による再生スケジュール・履歴追加、読み辞書の未保存プレビューと保存を確認。ブラウザーで見つかった初期化順の問題を修正した。英語モードでは英文表示、約2.42秒での再生スケジュール、履歴追加を確認。生成中の停止後に古い文が再生・履歴追加されないことを確認した。両環境の依存整合性、Python/JavaScript構文、47ファイルのソースZIP整合性と私的データ除外も確認した。検証用の登録音声と辞書項目を削除し、元の日本語/Irodori/本人の声の選択へ戻した。

## 設計から具体化した点

- ワーカーは自動割当のloopbackポートと起動トークンを使う。終了は所有プロセスのハンドルで管理し、親終了も監視する。
- unloadは重みだけの解放ではなく、所有ワーカーの終了でGPUを確実に解放する。
- 参照の文字起こしは第一版では利用者が入力。ASRの自動導入はしない。
- Irodoriの既存フラット設定は保持し、OmniVoiceパスを追加する方式。保存時に旧設定バックアップを作る。既存環境を一度に入れ替えない。
- モデル未読込でも受付でき、ジョブ状態で準備を表示する。参照情報のないOmniVoice発話は明示的に拒否し、別の声へ切り替えない。
- 通常の短文は完成WAV方式。ストリーミングの独自改造は行っていない。
