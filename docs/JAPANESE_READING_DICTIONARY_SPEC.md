# 日本語読み辞書 詳細仕様

作成日: 2026-10-19。実装前。関連: [統合設計](OMNIVOICE_INTEGRATION_DESIGN.md)、[検証計画](OMNIVOICE_VALIDATION_PLAN.md)。

## 1. 基本方針

原文を表示・翻訳・再編集の正とし、日本語TTSへ渡す`speech_text`にだけ読みを適用する。IrodoriとOmniVoiceは同じ辞書サービスを使う。

例: 原文「日本橋で集合します。」に、単語「日本橋」→読み「にほんばし」を登録した場合、表示原文は変えず、TTSへ「にほんばしで集合します。」を渡す。

日本語モードでは辞書を既定オンとする。英語に翻訳モードでは日本語原文をそのまま翻訳し、日本語辞書を通さない。英語発音辞書・翻訳用語集・ピッチアクセント指定は別機能であり本仕様の範囲外。

既存辞書のsurface/readingと最長一致・一回置換という動作を移行の基準にする。保存済みの項目を勝手にかな変換・削除しない。

## 2. データ

辞書はアプリ全体で一つ。最大100項目を第一版で維持する。

```json
{
  "schema_version": 2,
  "revision": 7,
  "entries": [
    {
      "id": "read-nihonbashi",
      "surface": "日本橋",
      "reading": "にほんばし",
      "match_mode": "substring",
      "enabled": true,
      "note": "東京の地名"
    }
  ]
}
```

| 項目 | 制約 |
| --- | --- |
| id | サーバー発行の不変ID。更新時に維持 |
| surface | NFC正規化後1〜40コードポイント。空白だけ・改行・制御文字不可 |
| reading | NFC正規化後1〜80コードポイント。新規/読み編集時はかな＋許容記号を基本とする |
| match_mode | substring または whole_text |
| enabled | falseの項目は照合しない |
| note | 任意。最大100コードポイント。発話へ渡さない |
| revision | サーバー採番。編集・削除・有効切替・順序変更の保存で増加 |

新規readingの許容集合: ひらがなU+3041〜3096、カタカナU+30A1〜30FA、繰返し記号ゝゞヽヾ、長音ー、中点・、日本語の句読点、通常空白。結合濁点はNFC後に検証する。少なくともかな1文字を含む。半角かなは保存前に利用者が全角へ直す。数字・漢字・英字は「読みをかなで入力してください」として新規登録を拒否する。

surfaceは通常の日本語・英語名・数字も許容し、大文字小文字を区別する。正規表現は受け付けず、全項目を文字列として扱う。モデル制御に使われる`[` `]` `<` `>`、制御文字は新規surface/readingとも許容しない。入力文に制御トークン風文字列がある場合の扱いは、各エンジンの通常テキスト入力検査で別途拒否または安全に扱う。辞書でエンジン命令を注入しない。

## 3. 照合と置換

1. 原文はそのまま保持。処理対象だけ改行コードをLFへ、UnicodeをNFCへ正規化する。NFKCや漢字の自動かな化は行わない。
2. enabled項目だけ取り出し、`surface`のコードポイント数が長い順、同長は辞書の保存順で並べる。
3. 原文を左から右へ走査し、その位置で一致する最初の項目を適用する。whole_textは正規化後の文全体がsurfaceと一致する場合だけ候補にする。
4. 一致部分をreadingで置換し、元の一致長だけ進める。置換後readingを再走査しない。未一致文字はそのまま出力する。
5. 完成文にかな・英数字・漢字などの発話可能文字があること、長さ320以内、モデルの入力制限内であることを確認する。

同じNFC surface＋match_modeは有効/無効を問わず重複不可。同じsurfaceでsubstringとwhole_textが重なる場合はwhole_textを優先する。保存順の手動変更は第一版UIでは提供せず、データの並びを安定保持する。

複雑な文脈推定はしない。「今日」「生」「方」のような多義語は、短い単語の広域置換より「今日中」「生ビール」など長い表記の登録を勧める。whole_textは入力文全体への一致なので、末尾の句点の有無も一致条件になることを説明する。

### 期待する適用例

| 辞書 | 入力 | TTSへの文 |
| --- | --- | --- |
| 日本橋→にほんばし | 日本橋で集合します。 | にほんばしで集合します。 |
| 日本橋→にほんばし / 日本→にほん | 日本橋と日本 | にほんばしとにほん |
| 今日→きょう / 今日中→きょうじゅう | 今日中に連絡します。 | きょうじゅうに連絡します。 |
| はし→ばし / 橋→はし | 橋 | はし（再置換しない） |
| AI→えーあい | AIとai | えーあいとai |
| 明日→あす、whole_text | 明日 | あす |
| 明日→あす、whole_text | 明日。 | 明日。（完全一致しない） |
| 日本橋→にほんばし、無効 | 日本橋 | 日本橋 |

辞書に正規表現を使わないことは、将来その実装にregexを使う場合も変わらない。内部の検索パターンでは必ずエスケープする。

## 4. 適用時点と例外

| 処理 | 辞書の扱い |
| --- | --- |
| 日本語発話の受付 | revisionとentriesを固定し、確定speech_textを作る |
| 日本語の定型句事前生成 | 同じサービスを使いrevisionをキャッシュキーへ含める |
| 英語に翻訳 | 原文にも英文にも日本語読み辞書を適用しない |
| 参照録音の文字起こし | 録音内容の正確な文字起こしを保持。適用しない |
| 保存済み履歴の再生 | 当時の音声を再生。現辞書で再合成しない |
| 履歴から「編集して再発話」 | original_textを入力へ戻し、次回受付時の辞書を適用 |
| 辞書項目の試聴 | 指定項目を含むドラフトでプレビューし、一時speech_textを合成 |

発話ごとの「今回だけ読みを指定」は将来機能とする。第一版は辞書編集と辞書オン/オフのプレビュー比較を提供し、通常ジョブは設定済み辞書を使う。

試聴は辞書保存と別操作。未保存ドラフトであることを表示し、試聴ジョブは履歴・定型句キャッシュへ保存しない。試聴も通常GPUキューを通し、通常発話の先頭へ割り込ませない。

## 5. APIと画面

`GET /api/v2/reading-dictionary`でrevisionとentriesを取得。

`PUT /api/v2/reading-dictionary`は`expected_revision`＋entriesを受け、全件検証後に一つのDBトランザクションで保存する。版が違えば409、入力不正なら422。部分保存しない。空entriesは全件削除でありrevisionを進める。

`POST /api/v2/reading-preview`は保存辞書またはドラフトを使う。返す情報:

```json
{
  "dictionary_revision": 7,
  "original_text": "日本橋で集合します。",
  "speech_text": "にほんばしで集合します。",
  "applied_entries": [
    {"entry_id": "read-nihonbashi", "surface": "日本橋", "reading": "にほんばし", "count": 1}
  ],
  "warnings": []
}
```

要求は`text`, `mode`, `use_dictionary`を必須、`draft_entries`を任意とする。ドラフトは保存せず、返すrevisionはnullにする。英語modeでは原文をそのまま返し、日本語辞書非適用を明示する。翻訳そのものはプレビューAPIでは実行しない。

画面には「単語」「読み」「有効」「適用範囲」「メモ」、追加・削除・保存、例文入力、適用後の文、適用項目一覧、試聴を置く。通常の発話画面に一覧を常時展開せず、「読みを確認」から開く。

「保存」と「試聴」を分け、試聴によりドラフトを勝手に保存しない。競合409なら最新を再読込し、未保存内容を保持して再編集できるようにする。

## 6. 移行と互換性

旧`Preferences.dictionary`を一回だけv2テーブルへ移す。各項目へID・enabled=true・match_mode=substringを付与。旧readingがかな以外でも、そのまま移す。既存利用者の設定を消さない。

旧形式の任意文字readingには`legacy_reading`属性をサーバー内部で付け、未編集なら保持可能とする。通常の文字列は互換動作を維持し、モデル制御記号・制御文字が含まれる場合はジョブ受付時に適用不可として明示する。新規追加・reading変更時は新制約へ合わせる。surface変更だけで旧readingを暗黙変換しない。

移行時にNFC正規化で衝突する項目は、旧配列の先頭を有効にし、残りを移行バックアップへ保存して注意を表示する。元設定はバックアップ済みのまま保持し、黙って失わない。衝突がなければ件数・順序を維持する。

既存の`GET/PUT /api/preferences`は辞書の互換ビューを返す。legacy PUTのdictionaryが現在の投影と同じならv2の追加情報を保持する。異なる場合、GET時に返したETagをIf-Matchへ付けることを必須にし、未指定428、競合412で上書きを防ぐ。既存UIは先行更新してETagを保持する。古いクライアントの辞書変更は再読込を案内する。

legacy経路で実際に辞書が変更された場合も、対応するsurfaceのIDとenabled/match_mode/noteを保ち、新項目だけ既定値で追加する。revisionはv2と共通。設定全体と辞書の更新は同じトランザクションで確定する。v2へ移した後は旧JSONを第二の正として読まない。

## 7. キャッシュと履歴

ジョブ受付で辞書版と適用結果を固定するため、キュー待機中の辞書編集はそのジョブに影響しない。キャッシュ生成完了時に現在の辞書でキーを計算し直さず、ジョブの固定値を使う。

辞書を変更した場合、定型句は「再準備が必要」と表示する。過去版の定型句音声を現行版として使わない。古いキャッシュはLRU/容量上限で整理する。履歴の音声は辞書キャッシュと別物であり自動削除しない。

履歴には当時のoriginal_text/speech_text/reading_revisionと適用項目の最小情報を保存できる。全文辞書は履歴へ複製しない。履歴保存オフなら、プレビューや自由文を辞書ログとして永続化しない。

## 8. 限界

かな指定でもモデルが必ず正しく読むとは限らない。アクセント・抑揚・助詞の読みの品質は実聴で確認する。人名や地名は利用者が意図した読みを登録し、自動推測で確定しない。

辞書を増やすことで別の語に誤適用することがある。適用項目の表示、無効化、長い表記、whole_textで対処する。高度な文脈条件や形態素解析を第一版の隠れた依存にしない。
