# Qwen3統合検証（2026-10-30）

## 構成

qwen3_fastアダプター → 認証付きローカルワーカー → ジョブごとのHTTPバイナリストリーム → AudioWorkletのPCM再生。制御・取消は既存HTTP APIを使用します。WebSocketは使用しません。OmniVoiceは既存の完成WAV経路を維持します。

フレームはJSONメタデータ長（4バイトBE）、JSON、PCMの順です。24kHz・モノラル・PCM16、順序番号を検証します。サーバーのフレーム保持量・ブラウザーの再生バッファ・生成秒数に上限があります。クライアント所有権、Host/Origin検証、切断時取消、世代番号による古い再生の抑止を適用します。

完成したWAVだけを履歴・キャッシュへ渡します。モデルID・参照音声・生成設定・実装identityでキャッシュを分離します。

## 実モデルAPI検証

通常の個人データから分離したポート8112のデータ領域と、4.92秒の合成参照音声を使用しました。

| 操作 | 結果 |
| --- | --- |
| Qwenの声準備 | ready |
| 逐次生成 | 最初のPCM 372.96ms、完了4435.17ms、19チャンク |
| PCM整合性 | 連結PCMと完成WAVの波形バイトが完全一致 |
| 最初のPCM後に取消 | cancelled、完成音声APIは410 |
| 取消後の再生成 | 成功、PCM一致。最初1026.53ms、完了4840.50ms |

最初のPCM時間と全体生成時間は異なります。取消直後の値には前処理の終了待ちも含まれます。証拠JSON・音声は .runtime/qwen-integration/ に置き、ソース配布へ含めません。

## ブラウザーと自動検証

実ブラウザーでQwen選択、速度欄の無効化、発話、履歴への追加、再生完了を確認。初回の表示は再生開始0.49秒、コンソールの警告・エラーなしでした。途中停止で履歴が増えず、次の発話も再生できました。これは再生スケジュールの観測で、物理出音・聴感の保証ではありません。

Pythonテスト50件が成功。短いreadへの対応、切断・フレーム上限、途中取消、未完了音声を確定しないこと、所有権・Origin拒否、エラーフレームを含みます。JavaScript構文チェックも実施しました。

新規PCでの全ダウンロード導入、人による聴取、実録音との声の類似性、Discord経由の音声、長時間連続使用、統合後の英語翻訳発話は未検証です。以前のモデル単体評価とアプリ統合検証は区別してください。
