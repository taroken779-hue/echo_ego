関連: [統合設計](OMNIVOICE_INTEGRATION_DESIGN.md)、[読み辞書仕様](JAPANESE_READING_DICTIONARY_SPEC.md)。

## 1. 段階と完了条件

| 段階 | 作業 | 完了条件 |
| --- | --- | --- |
| A. 現行保護 | 現設定・辞書・声ID・既存APIの記録、移行バックアップ | 現行Irodoriへ戻せる。録音を上書きしない |
| B. 辞書分離 | 旧辞書移行、適用関数、版更新、プレビュー | 原文を保持し、最長一致・非再帰・英語非適用が成立 |
| C. OmniVoice単独実証 | 専用環境、固定モデル、参照準備、日英WAV | 非ゼロ音声とモデル版を確認。音質合格とは分ける |
| D. 共通管理 | アダプター、ワーカー、ジョブ、取消、キャッシュ | 二重生成や古い音声再生がなく、Irodori互換が維持 |
| E. 日本語A/B | 同一条件で自然さ・読み・似方・速度を比較 | 本人の実聴と測定結果を記録 |
| F. 英語モード | 翻訳器の選定、原文/訳文表示、英語発話 | 翻訳前かな化がなく、意味と声と待ち時間が許容範囲 |

## 3. 辞書と移行の必須確認

| 確認 | 期待結果 |
| --- | --- |
| 日本橋/日本の重なり | 長い表記が優先 |
| 橋→はし、はし→ばし | 橋は「はし」で止まり、再置換しない |
| 日本語原文→英語 | 翻訳器が受け取るのは元の漢字かな交じり文 |
| 原文/履歴表示 | かな置換により原文が失われない |
| 保存後にキュー内文を実行 | 受付済み文は旧辞書、新規文は新辞書 |
| キャッシュヒット後に読み編集 | 新規発話で古い読みの音声を返さない |
| NFC衝突、重複項目、不正reading | 明示エラーまたは規定の移行注意。部分保存しない |
| 試聴ドラフト | 辞書・履歴へ勝手に保存しない |
| 旧設定移行/再起動/巻き戻し | 既存声ID・辞書・設定が保持される |
| 旧APIとv2からの同時編集 | ETag/expected_revisionで更新消失を防ぐ |
| 160/320/640文字境界 | コードポイント計数を統一、超過は切捨てない |

辞書適用はGPUなしの単体検証、APIは一時DBと偽エンジンで確認する。比較音声の単なる存在を正しい読みの証拠にしない。

## 4. 日本語A/B条件

比較対象は現在のIrodori-TTS-v4.1-Small-MFと導入時に固定したOmniVoice。Irodoriは現行4stepを基準、OmniVoiceは32stepと16stepを別条件で測る。高速化の有無、dtype、seed、後処理を記録し、混ぜて集計しない。

参照は本人の日本語録音と既存生成プロファイルを分ける。共通の3〜10秒区間で比較し、さらに各モデルで適切な参照長の結果も補助評価として出す。Irodoriに適した長い参照を使う条件と短い参照条件を混ぜない。

日本語セット案: 30文以上。短い応答、普段の会話、疑問/否定、漢字の多義語、人名/地名、日時/金額、英数字混在、句読点/括弧を含める。

同じセットを「辞書なし」「同じ訂正辞書あり」の両方で生成する。辞書なしはモデルの読み能力、辞書ありは実利用の成立性として分ける。試行後の辞書追加で片方だけ有利にした結果を比較しない。

最低3回ずつ測定し、音声をA/Bの名前でランダム化して本人が聴取する。評価軸は自然さ、読み誤り、声の似方、余計な発話/欠落、先頭/末尾ノイズ。評価者と採点基準を記載する。自動ASR・話者類似度は補助とする。

## 5. 応答性能

測定区間を分ける:

```text
Enter → 受付 → 辞書適用/翻訳 → モデル待ち/切替 → 声準備
      → 推論 → WAV受信 → 再生スケジュール → 先頭の有音
```

ブラウザー値にはポーリング間隔・受信・decodeを含める。物理スピーカーの開始時刻はループバックや外部録音で別に測る。公称RTFや既存の過去記録を今回の発話時間へ置き換えない。

記録: p50/p95とサンプル数、全文生成時間、音声長/RTF、先頭無音、最大VRAM/RAM、モデル切替時間、参照準備時間、取消後に次文を処理できるまで。コールド/ウォーム、キャッシュ命中、翻訳有無を分ける。

仮の体感目標: 待ち行列なし・声準備済み・短文で日本語p50 1秒以下/p95 2秒以下、英語翻訳込みp50 1.5秒以下/p95 3秒以下。これは合否の仮目標で、実現予測や保証ではない。実測が届かなければ、待ち区間の内訳から改善策と目標を見直す。

OmniVoiceの日本語標準化は、Irodoriに対して重大な読み誤り・余計な発話が増えず、本人が声/自然さを許容し、応答時間が実用範囲である場合に提案する。得意分野が分かれれば日英または声ごとの使い分けを残す。

## 6. 統合動作と故障時

- 連投で順序が変わらない。409再試行・ネットワーク再送で同じ要求を二重生成しない。
- 生成中Esc、ready直前Esc、モード変更、声削除、辞書保存、タブ再読込を確認する。
- OOM、翻訳タイムアウト、ワーカー異常終了、無効WAV、無音、長すぎる音声を失敗として表示する。
- 停止できない推論も古い結果を再生・キャッシュ保存しない。再起動対象は所有ワーカーだけ。
- モデル切替で受付済みジョブが別エンジンへ変わらない。
- 履歴保存オフで自由文の原文・訳文・音声がディスクへ残らない。通常ログと一時ファイルも確認する。
- 参照音声・本人プロンプト・DB・モデル・ローカル設定が配布ZIPとGit stagingへ入らない。

## 7. その後に残る判断

英語の意味の正確さ、クロス言語の声、実スピーカー/通話アプリへの出力、別Windows環境での導入、モデル利用条件と配布方針をそれぞれ別に確認する。設計文書・単体テスト・WAV生成の成功だけでこれらを完了扱いにしない。
