## 確認した範囲

開発PCはWindows・RTX 5080・16GB。公式Irodoriの固定ソースと専用.venv（Python 3.11、PyTorch 2.10.0+cu128）を使います。既存環境とは別に構築し、uv pip checkで依存の整合性を確認しました。

6件の単体テストで、履歴保存オフ時の拒否・音声削除、件数/期間/容量の上限、DBを開き直した復元と削除取り消し時の生成日時保持、声名変更時のキャッシュ維持と声削除時の整理、定型句キャッシュ上限、設定の不正値を検証しました。

実GPUのAPI検証では説明文から設計したプリセット、48kHz・非ゼロ信号のWAV、読み辞書を適用した生成、定型句の再利用と変更時の再生成、履歴音声の保存・取得・削除、試験用WAVの登録・名前変更・お気に入り・試聴用取得・削除、外部Origin/Hostの拒否を確認しました。試験用音声を削除し、既存の本人登録WAVは保持しています。

ブラウザーでは生成中に2文目を送信し、順に再生されて両方の履歴が作られることを確認しました。履歴保存オンで再読み込み後の日時・音声復元、削除・取り消し・再生も確認しました。検証後は履歴保存を標準のオフに戻しています。アプリ内の導入マニュアルとテーマ表示を確認しました。

同じ文のAPI取得は、透かし有効の最終検証で初回約0.98秒、キャッシュ利用時約0.006秒でした。元の生成日時を保持して返すことも確認しました。ブラウザーの事前生成した定型句では再生スケジュールまで約0.02秒を確認しました。先頭無音・出力機器の遅延が加わるため、実際に聞こえ始める時間とは異なります。平均性能の保証でもありません。

ブラウザーで待ち文の個別取り消しとEsc停止を行い、停止した文章が後から履歴に追加されないことを確認しました。定型句の並べ替えが再読み込み後も残ること、終了APIで8100のポートが解放されることも確認しました。配布ZIPは31ファイルで、ZIPの整合性と個人データの除外を確認しました。

未使用の女性プリセットを「試聴」から初回生成し、ブラウザーの再生開始と参照WAVの保存を確認しました。これは実際に人間が聞いて声の品質を評価した結果とは区別します。

## 導入時に見つけて修正した問題

Python 3.12では固定版SentencePieceのWindows用バイナリーがなくビルドに失敗するため、セットアップは3.11に固定しました。

SilentCipherはsnapshot_downloadをファイルの絞り込みなしで呼びます。新しいHugging Faceライブラリーのオフライン確認では、一部だけ取得したキャッシュを不完全と判定するため、固定スナップショットを完全に取得するよう修正しました。透かしの利用状態はAPIで確認でき、未読込の場合は発話画面の詳細に表示します。
