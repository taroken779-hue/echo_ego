# TTSモデルの交換に対応する設計・Irodori廃止タスク

更新日: 2026-10-22

状態: 実装・設定移行・ローカル検証済み。Irodori専用物は復元可能な保管先へ退避。詳細と未検証項目は[TTS_BACKEND_VALIDATION.md](TTS_BACKEND_VALIDATION.md)を参照。

従来の「OmniVoice専用化」計画を、この計画で置き換える。現在利用する実装はOmniVoiceとし、将来Qwen TTSなどへ交換・追加できる境界を用意する。Qwenの具体的な製品・版・機能は未選定であり、その導入や機能互換は今回の完了条件に含めない。別PCの初回導入・CPU・人の実聴・通話は未実施として検証記録に明記した。チェックはその確認範囲を含むタスクの処理完了を表す。

## 基本方針

- アプリ共通部分は、キュー、取消、辞書、翻訳の呼び出し、履歴、定型句、再生を担当する。
- TTSバックエンドは、モデル固有の読み込み・声準備・入力検証・推論・出力変換を担当する。OmniVoiceを最初の実装にする。
- バックエンド実装IDと、重み・版・実行設定を持つモデル構成IDを分ける。同じバックエンドで別の重みを選ぶ場合に実装を複製しない。
- 言語、参照音声、文字起こし、声の生成、話速、ステップなどの対応可否・制約を能力情報として返す。モデル名で共通コードを分岐させない。
- 翻訳とASRをTTSから独立したサービス境界に置く。TTSの交換で翻訳・ASRまで交換する必要がない構成とする。
- 初回はローカルPythonの隔離ワーカーと完成WAV方式を維持する。複数モデルの同時GPU常駐、リモート実行、ストリーミング、プラグインの自動探索は今回の対象外とする。
- 初期選択はOmniVoiceとし、未導入・非対応・参照未準備の場合は明示する。別のモデル・声へ自動的に切り替えない。

## 目標とする責務の境界

| 層 | 責務 | モデル交換時の扱い |
| --- | --- | --- |
| 画面・公開API | モード、声、モデル構成の選択、共通ジョブ操作 | 能力情報と設定定義に従う |
| 発話サービス | 辞書、翻訳、要求の固定、キュー、キャッシュ、履歴 | 原則変更しない |
| 実行環境管理 | 所有ワーカーの開始・停止、排他、切替、監視 | 登録された構成を起動する |
| TTSバックエンド | 入力制約、声準備、モデル読み込み、推論、出力 | 追加モデル用の実装を追加する |
| 翻訳・ASRサービス | 訳文作成、参照区間の文字起こし | TTSと独立して利用する |
| 声の保存 | 元音声・区間・文字起こしと、モデル別の準備結果 | 元素材を保持して必要な準備を行う |
