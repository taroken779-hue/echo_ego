## 目的と維持する機能

日本語・日英翻訳後の英語発話をOmniVoiceへ一本化する。発話キュー、取消・全停止、登録音声、参照区間・文字起こしの自動入力、読み辞書、定型句、履歴、出力先選択は維持する。

録音、参照設定、声の名前・お気に入り、辞書、定型句の文章、保存済み履歴は移行対象とし、削除しない。既存のStudioなど、Echo Ego外の環境は変更しない。

## T1: 移行方式と既存データの確認

- [ ] 設定・DB・声の参照設定の構造と使用箇所を確認し、バックアップ対象と復元手順を定める。
- [ ] 日本語エンジン設定をOmniVoiceへ移す。旧設定を読み込める移行処理にし、繰り返し実行しても値を壊さない。
- [ ] 標準4声の生成済みWAVの有無、参照区間・文字起こし、3〜10秒の条件を確認する。
- [ ] 新規インストール時の標準音声を、OmniVoiceの音声生成へ置き換える方式で検討・小規模検証する。既存の声と同じ声質になるとは扱わない。実現できない場合は、利用可能な参照音声を用意する方式または録音登録から開始する方式を比較して決める。
- [ ] 旧 `/api/speech` の利用箇所を洗い出し、アプリ内はジョブAPIに統一する方針と、旧APIの互換対応または廃止時の応答を決める。

完了条件: データ保持方針、標準音声の作成方式、APIの移行方針、復元手順が具体化している。

## T2: セットアップとPython環境の独立化

依存: T1

- [ ] `setup.bat` / `scripts/setup.ps1` を、Irodoriを取得せずアプリ本体とOmniVoiceを導入できる構成へ変更する。
- [ ] アプリ本体用PythonとOmniVoice用Pythonの役割を明確にする。現在の `.venv` は起動にも使うため、この段階で削除しない。
- [ ] `scripts/start.ps1`、設定例、導入済み判定を新構成へ合わせる。
- [ ] Irodori専用設定と共通設定を分け、旧 `config.local.json` をバックアップ付きで移行する。ポート、オフライン、デバイス、起動時読み込みなどは維持する。
- [ ] OmniVoice・Codec・翻訳・ASRの固定版取得と、再実行時の既存設定保持を確認する。

完了条件: Irodoriが存在しない構成で、アプリとOmniVoiceを導入・起動できる。

## T3: 音声生成処理とAPIの一本化

依存: T1、T2

- [ ] `speech/runtime.py` / `speech/worker.py` からIrodoriの読み込み・推論・特徴抽出とエンジン間の切替処理を除去する。
- [ ] `app.py` の起動時読み込み、標準音声作成、旧発話経路、状態・診断APIをOmniVoice構成へ変更する。
- [ ] `speech/service.py` のエンジン入力・ステップ検証・モデル情報を一本化する。旧Irodori指定を黙って受理しない。
- [ ] 既存のFIFO、取消後の結果破棄、要求IDの重複防止、推論と参照準備・ASRの直列実行を維持する。
- [ ] キャッシュ識別子を更新し、旧Irodori音声を新しいOmniVoice生成結果として返さない。

完了条件: 日本語・日英翻訳・辞書試聴・定型句のすべてがIrodoriなしで生成できる。

## T4: 声と保存データの移行

依存: T1、T3

- [ ] 標準音声の新規作成を実装し、既存WAV・手動参照設定は優先して保持する。
- [ ] 既存の登録音声について、準備済み／参照設定が必要／録り直しが必要を判別できるようにする。利用できない声を別の声へ自動置換しない。
- [ ] 3秒未満の録音には録り直し案内、長い録音には3〜10秒の区間選択を提供する。
- [ ] 履歴のWAVと当時のエンジン情報を保持する。履歴をOmniVoice生成として書き換えない。
- [ ] 定型句の文章・辞書を保持し、OmniVoice用の事前生成を案内する。

完了条件: 既存データが残り、移行後に使える声と追加準備が必要な声が分かる。
