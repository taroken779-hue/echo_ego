# Qwen3-TTS（低遅延）

音声全体の完成前から再生する追加モデルです。標準のOmniVoiceも引き続き選べます。Qwen3-TTS 0.6B Baseに、第三者実装faster-qwen3-ttsのCUDA Graphs・逐次生成を組み合わせています。

## 導入と切り替え

1. 通常の `setup.bat` でEcho Egoを導入します。
2. アプリを `stop.bat` で停止し、`setup_qwen3.bat` を実行します。初回は専用Python環境とモデルをダウンロードします。NVIDIA CUDA GPU専用です。
3. `start.bat` で起動します。設定の「音声モデル・実行環境」で「Qwen3-TTS（低遅延）」を選択します。
4. 声を選び、準備完了を待って発話します。初回・モデル切り替え直後はモデル読込とCUDA Graphsの準備に時間がかかります。

この開発PCでは追加導入済みです。起動・終了はこれまでと同じ `start.bat` / `stop.bat` を使用します。追加セットアップは選択済みモデルを勝手に変更しません。OmniVoiceへの切り替えも同じ設定欄です。GPU上のモデルは切り替え時に入れ替わります。

## 声と生成設定

- 参照音声は3〜10秒の区間と、その区間に一致する文字起こしを設定します。既存のWAVも条件が合えば使用できます。長い録音は「声」画面で区間を指定します。
- 日本語・英語に対応します。英語に翻訳する場合は、翻訳処理の時間が追加されます。
- 詳細欄のチャンクサイズは4または8です。標準は4。音声を小分けに受信し、AudioWorkletで順番に再生します。
- 話す速さの変更と声のデザインは、このアダプターでは非対応です。速度欄は無効になります。
- 停止・Escは受信と再生を中断します。途中までの音声を履歴や定型句キャッシュへ保存しません。生成処理の停止反映を待つため、直後の次の発話が遅れることがあります。
- 完成した発話は通常どおり履歴から再生・WAV保存できます。生成済み定型句は完成WAVを再利用します。

## 性能と制約

今回の統合検証では最初のPCM受信が約0.37秒、ブラウザー表示の再生開始が約0.49秒でした。文章・GPU・声・待ち行列で変わる単発値で、物理的な出音の測定ではありません。生成音声の先頭無音も加わります。

評価では一部の文で語の重複がありました。短文から試し、用途に合う音質・発音・声の類似性を確認してください。人による聴取評価やDiscord通話の実機確認は未実施です。1発話30秒以内、生成トークン数に上限を設けています。

## 実装とトラブル対応

モデルIDは `qwen3`、バックエンドは `qwen3_fast` です。アプリ・OmniVoiceと別の `runtime/qwen3-fast/.venv` を使い、モデルは `runtime/qwen3-tts/model-0.6b` に保存します。

検証済み組み合わせはfaster-qwen3-tts 0.5.4、qwen-tts-hf 0.1.1.post1、transformers 5.15.1、PyTorch 2.10.0+cu128です。公式のqwen-ttsとqwen-tts-hfを同じ環境へ混在させないでください。依存バージョンを固定しているため、更新は再検証が必要です。

準備に失敗する場合は参照区間・文字起こしを確認し、アプリを停止してセットアップを再実行します。GPUメモリ不足の場合は他のGPUアプリを終了してください。初回取得後の発話はローカルで処理します。
